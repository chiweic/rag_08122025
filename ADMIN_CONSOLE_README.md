# Admin Console - Real-time Analytics Dashboard

## Overview
The Admin Console provides real-time monitoring and analytics for the DDM RAG system by reading query logs generated by `query_logger.py`. No additional database tables required - all data comes from existing JSON log files.

## Access

**URL:** `http://localhost:8000/admin`

### 🔒 Authentication Required

The admin console is protected with HTTP Basic Authentication. When you access the URL, your browser will prompt for credentials.

**Default Credentials:**
- Username: ``
- Password: ``

⚠️ **IMPORTANT**: Change the default password in production!

To customize credentials, set these environment variables in `.env`:
```bash
ADMIN_USERNAME=your_username
ADMIN_PASSWORD=your_secure_password
```

## Features

### 📊 Real-time Metrics (Last 24 Hours)
- **Total Queries**: Number of queries in the last 24 hours
- **Unique Users**: Number of distinct users (authenticated + anonymous)
- **Avg Response Time**: Average computation time per query
- **Active Now**: Number of queries in the last 15 minutes

### 📈 Visualizations

1. **Hourly Query Activity (24h)**
   - Line/bar chart showing query volume by hour
   - Toggle between chart types
   - Real-time updates every 30 seconds

2. **User Type Distribution (24h)**
   - Doughnut chart showing authenticated vs anonymous users
   - Percentage breakdown

3. **7-Day Query Trend**
   - Bar chart comparing daily queries and unique users
   - Historical view of system usage

4. **Recent Queries Table**
   - Last 20 queries with timestamps
   - User identification
   - Query text preview
   - Source count and computation time

### 🔄 Auto-Refresh
- Dashboard automatically refreshes every 30 seconds
- Manual refresh button available
- Last update timestamp displayed

## Data Source

All analytics are derived from query logs stored in:
```
logs/
├── queries/           # Individual query JSON files
│   ├── 20251104_141234_567890.json
│   ├── 20251104_142345_678901.json
│   └── ...
└── daily/            # Daily text logs
    ├── 2025-11-04.log
    └── ...
```

### Query Log Format
Each query is stored as a JSON file with the following structure:
```json
{
  "query_id": "20251104_141234_567890",
  "timestamp": "2025-11-04T14:12:34.567890",
  "user": {
    "ip_hash": "a1b2c3d4e5f6g7h8",
    "ip_raw": "192.168.1.100",
    "authenticated": true,
    "user_email": "user@example.com"
  },
  "query": {
    "question": "什麼是禪修？",
    "retrieval_mode": "rag",
    "character_count": 6,
    "word_count": 3
  },
  "result": {
    "answer": "...",
    "answer_length": 500,
    "sources_count": 5,
    "computation_time": 2.34
  },
  "sources": [...]
}
```

## Performance

### Advantages of Log-based Analytics
✅ **No Database Overhead**: Reads directly from JSON files
✅ **No Schema Changes**: Uses existing `query_logger.py` infrastructure
✅ **Fast Implementation**: Only 3 API endpoints needed
✅ **Easy Debugging**: Human-readable JSON logs
✅ **No Data Migration**: Works with historical data immediately

### Scalability Considerations
- Efficient for < 10,000 queries/day
- File-based parsing is fast enough for admin dashboards
- For higher volume, consider:
  - Log aggregation service (e.g., Elasticsearch)
  - In-memory cache for frequent queries
  - Database migration for long-term storage

## Troubleshooting

### Dashboard shows "No data"
- **Check logs exist**: Verify `logs/queries/` contains JSON files
- **Check date range**: Ensure queries exist in the last 24 hours
- **Check file permissions**: Ensure FastAPI can read log files

### Charts not updating
- **Check auto-refresh**: Should refresh every 30 seconds
- **Check console errors**: Open browser DevTools → Console
- **Check API endpoints**: Test endpoints directly with curl

### Slow performance
- **Log file count**: If > 50,000 files, consider cleanup
- **Disk I/O**: Check if disk is slow
- **Optimize**: Add caching layer or use database

## Security Considerations

✅ **Authentication Implemented**: The admin console is protected with HTTP Basic Authentication.

### Current Security Features:
1. ✅ **HTTP Basic Authentication**: All admin routes require username/password
2. ✅ **Timing Attack Protection**: Uses `secrets.compare_digest()` for credential comparison
3. ✅ **Environment Configuration**: Credentials stored in `.env` file (not hardcoded)

### Additional Recommended Security Measures:
1. **Change Default Password**: Update `ADMIN_PASSWORD` in `.env` immediately
2. **IP Whitelisting**: Restrict to internal network only (firewall/nginx configuration)
3. **HTTPS**: Use SSL/TLS in production (required for Basic Auth security)
4. **Rate Limiting**: Prevent brute-force attacks on auth endpoint
5. **Audit Logging**: Track admin access attempts (successful and failed)
6. **Session Management**: Consider upgrading to JWT tokens for better session control

### Authentication Implementation:
The current implementation uses FastAPI's `HTTPBasic` security:
```python
# In api.py
from fastapi.security import HTTPBasic, HTTPBasicCredentials
import secrets

security = HTTPBasic()

def verify_admin_credentials(credentials: HTTPBasicCredentials = Depends(security)):
    correct_username = secrets.compare_digest(credentials.username, ADMIN_USERNAME)
    correct_password = secrets.compare_digest(credentials.password, ADMIN_PASSWORD)
    if not (correct_username and correct_password):
        raise HTTPException(status_code=401, detail="Incorrect username or password")
    return credentials.username
```
